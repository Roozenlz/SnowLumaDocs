SnowLuma is a Remote Protocol Framework for NTQQ, bridging QQ sessions into the OneBot v11 ecosystem with a structured API for bot development.

## What you can use it for

- **OneBot v11**: HTTP, WebSocket, reverse WebSocket, and HTTP event-reporting adapters.
- **NTQQ bridge**: capture and decode NTQQ packets through the hook, translate them to higher-level events and actions.
- **Multi-account sessions**: one OneBot instance per UIN, with per-account config that inherits from the global file.
- **Built-in WebUI**: the full build ships a web console for status, adapter management, and staged updates.
- **TypeScript SDK and MCP**: `@snowluma/sdk` is a typed OneBot client; `@snowluma/mcp` exposes the same action catalog to agents.

## Requirements

| Item | Required |
| --- | --- |
| Windows / macOS | Native run; bring your own Node.js |
| Linux | Runs [inside Docker](/docs/docker) only (the image bundles QQ + Xvfb + VNC) |
| Node.js | `^24.22.1` or `>=26.12.1` (bundled in the full distribution) |
| QQ | NTQQ with a visible window |

## Two ways to run it

| Use case | Recommended path |
| --- | --- |
| Server deployment | [Docker container](/docs/docker) — the image bundles QQ + Xvfb + VNC and works out of the box |
| Local prebuilt | Grab the matching tarball from [GitHub Releases](https://github.com/Roozenlz/SnowLuma/releases), unpack, run the launcher |

## Release asset names

Every tag publishes three platforms — Windows x64, Linux x64, and Linux arm64:

| File | Notes |
| --- | --- |
| `SnowLuma-<TAG>-win-x64.zip` | Windows full build with Node.js bundled |
| `SnowLuma-<TAG>-linux-x64.tar.gz` | Linux x64 full build |
| `SnowLuma-<TAG>-linux-arm64.tar.gz` | Linux arm64 full build |
| `...-lite.zip` / `...-lite.tar.gz` | No bundled Node.js; requires `^24.22.1` or `>=26.12.1` |

The full build unpacks and runs; the lite build is much smaller and suits containers or hosts that already have Node installed.

## Distribution layout

`pnpm build:all` writes to the repo root `dist/`:

```text
dist/
├─ index.mjs            # main entry
├─ launcher.bat         # Windows launcher
├─ launcher.sh          # Linux launcher
├─ package.json
├─ release.json         # release manifest (version, target, file list)
├─ webui/               # bundled WebUI assets
└─ native/              # platform natives
   ├─ snowluma-<platform>-<arch>.node
   ├─ snowluma-<platform>-<arch>.so / .dll
   └─ websocket-<platform>-<arch>.node
```

After unpacking, run `launcher.bat` on Windows or `./launcher.sh` on Linux.

## Quick start

1. Unpack the archive that matches your architecture.
2. Open `http://localhost:5099`.
3. Sign in with the initial credentials from the startup log, then attach the QQ process and configure OneBot.

For unattended deployments, set both `SNOWLUMA_ACCEPT_EULA=1` and `SNOWLUMA_ACCEPT_PRIVACY=1` to accept the bundled agreements up front; missing either one still shows the consent page.

## Default services

The first time an OneBot instance starts, SnowLuma creates `config/onebot.json`, `config/onebot_<uin>.json`, and `config/runtime.json`.

| Service | Default address | Config key |
| --- | --- | --- |
| OneBot HTTP | `http://0.0.0.0:3000/` | `networks.httpServers[].port` |
| OneBot WebSocket | `ws://0.0.0.0:3001/` | `networks.wsServers[].port` |
| WebUI | `http://0.0.0.0:5099/` | `runtime.json` → `webuiPort` |

See the [configuration reference](/docs/configuration) for every field.
